# 02 编译与烧录

## 一、在 VS Code 里编译

1. VS Code → 文件 → 打开文件夹 → 选 `project`；
2. 首次打开：底部弹 CMake 预设选择 → 选 **Debug**（工具链会自动从
   `CUBE_BUNDLE_PATH` 找到 GCC，无需手动配置）；
3. 点底部状态栏 **$(tools) 编译** 按钮（Task Buttons 插件），
   或 `Ctrl+Shift+B` 选 "STM32: 编译"；
4. 成功标志：终端出现 `[46/46] Linking ...` 和大小统计；
   产物：`build/Debug/project.elf`（烧录用）、`project.hex`、`project.bin`。

> 第一次打开时如果 CMake 没有自动配置：`Ctrl+Shift+P` → 输入
> "CMake: Configure" 回车，再编译。

## 二、烧录（ST-LINK + OpenOCD）

1. 接好 ST-LINK（4 根线），C 板由电池供电；
2. 点 **$(cloud-download) 烧录** 按钮（或 `Ctrl+Shift+B` 选"烧录"）；
3. 看到 `verified OK` / `shutdown command invoked` 且板子复位重启（蜂鸣器响）= 成功。

## 三、断点调试（可选，出问题时再用）

1. 在 `App/task_motor.c` 等文件里点行号左边打红点；
2. 按 `F5`（自动启动 OpenOCD GDB 服务器 → 烧录 → 停在入口）；
3. 顶部工具栏：继续 / 单步 / 查看变量；
4. 调试结束点红色方块停止，**OpenOCD 窗口也会自动关闭**；
   如果没关干净，任务管理器结束 `openocd.exe` 再试。

## 四、命令行备选（按钮不好使时）

```powershell
# 先进入工程根目录（下面的相对路径依赖这个目录）
cd C:\Users\Lenovo\Desktop\temporary\project

# 编译
D:\STM32Cube\VSCodeBundles\cmake\4.3.1+st.1\bin\cmake.exe --build build\Debug

# 烧录（注意：-c 里必须用相对路径或正斜杠，不能用 Windows 反斜杠路径，
#        因为 OpenOCD 会把 \ 当转义符，导致找不到文件）
D:\openocd\bin\openocd.exe -s D:\openocd\share\openocd\scripts -f interface/stlink.cfg `
  -c "transport select hla_swd" -c "adapter speed 1000" -f target/stm32f4x.cfg `
  -c "program build/Debug/project.elf verify reset exit"
```

> 也可以写成绝对路径，但**必须用正斜杠**：
> `-c "program C:/Users/Lenovo/Desktop/temporary/project/build/Debug/project.elf verify reset exit"`

**烧录前必须先结束占用 ST-LINK 的进程**（尤其是点过"调试"之后）：

```powershell
Get-Process openocd, stlinkserver -ErrorAction SilentlyContinue | Stop-Process -Force
```

## 五、路径与你的机器

配置里所有绝对路径都来自你的实际安装位置：

| 项 | 路径 | 若移动了软件改这里 |
|---|---|---|
| CMake | `D:\STM32Cube\VSCodeBundles\cmake\4.3.1+st.1\bin` | `.vscode/tasks.json` |
| GCC/GDB | `D:\STM32Cube\VSCodeBundles\gnu-tools-for-stm32\14.3.1+st.2\bin` | `.vscode/launch.json` |
| OpenOCD | `D:\openocd` | `.vscode/tasks.json` |

## 六、故障排查

| 现象 | 处理 |
|---|---|
| 按钮点了没反应 | `Ctrl+Shift+P` → "Developer: Reload Window" |
| 烧录提示找不到 ST-LINK | 换 USB 口；确认 C 板已上电；设备管理器看驱动 |
| `Error: open failed` | ST-LINK 没插好 / 被调试会话占用 |
| 编译报"找不到 arm-none-eabi-gcc" | 确认 `CUBE_BUNDLE_PATH` 环境变量存在，重启 VS Code |
| 中文路径报错 | 把整个 `project` 文件夹复制到纯英文路径再打开 |
